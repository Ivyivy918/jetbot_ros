# doc_translator — 用 Claude API 翻譯文件（含圖片內的文字）

一支命令列工具：把 **PDF / DOCX** 翻成指定語言，**版面盡量原封不動**，
而且 **圖片裡的文字也會翻譯，並且畫回它原本的位置**。
執行時會先問你這次翻譯有沒有特殊要求；沒有就留白，由 Claude 自行判斷。

```bash
pip install -r tools/doc_translator/requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...        # 或先跑 `ant auth login`
python -m tools.doc_translator 手冊.pdf
```

---

## 1. 設計目標

| 目標 | 具體要求 |
| --- | --- |
| 保留版面 | 譯文寫回原本的段落／文字框，不是輸出一份純文字譯稿 |
| 圖片也要翻 | 圖中文字辨識 → 翻譯 → **蓋回原位**，輸出的還是一張圖 |
| 一開始就能提要求 | 口吻、術語、讀者對象、格式慣例等，在第一步輸入，之後每一次 API 呼叫都帶著 |
| 沒提要求也能用 | 留白時交給模型自行判斷，不會卡住流程 |
| 成本可控 | 批次、快取、`--dry-run` 試算、可調 effort |
| 可自動化 | 全部設定都有對應參數／設定檔，`-y` 即可非互動執行 |

## 2. 整體架構

```
                    ┌──────────────┐
  使用者一開始的     │    cli.py    │  互動問答 / 參數 / YAML 設定檔
  「特殊要求」  ───► │   config.py  │  → 合併成一個 Config
                    └──────┬───────┘
                           │
              ┌────────────▼─────────────┐
              │         llm.py           │  · 把特殊要求組進 system prompt
              │  Translator（唯一對外    │  · 文字分批 + 並行
              │  呼叫 Claude 的地方）    │  · structured outputs 保證回傳格式
              └───┬──────────────────┬───┘  · 統計 token 與花費
                  │                  │
        文字：id→譯文          圖片：文字段落 + 正規化座標 + 譯文
                  │                  │
     ┌────────────▼───┐   ┌──────────▼──────────┐
     │ docx_backend.py│   │   imagetrans.py     │  量底色/字色 → 蓋掉 → 自動配字級寫回
     │ pdf_backend.py │◄──┤   （圖片重繪引擎）   │
     └────────┬───────┘   └─────────────────────┘
              │
        翻譯後的 .docx / .pdf     ── cache.py（sqlite 譯文快取）
                                  ── fonts.py（挑出畫得出目標語言的字型）
                                  ── report.py（統計與花費摘要）
```

模組職責切得很乾淨：**只有 `llm.py` 會呼叫 API**，後端只負責「拆出文字 / 把譯文放回去」，
所以要加第三種格式（HTML、PPTX…）時，只要再寫一個後端即可。

---

## 3. 三個核心設計決策

### 3.1 「特殊要求」怎麼進入每一次翻譯

使用者在第一步輸入的要求，會被放進 **system prompt 的最高優先區塊**，
而且明確宣告它可以覆蓋工具內建的一般規則：

```
【使用者的特殊要求】（最高優先；與一般規則衝突時以此為準）
    保持技術手冊的口吻；JetBot、ROS2 等產品名不要翻譯
```

沒有輸入時，這個區塊會換成「未指定，請依你的專業判斷…」，而不是留空 —— 留空會讓模型
猜測是不是漏了什麼。這段 prompt 對整個工作是固定的，因此掛上 `cache_control`
讓它走 prompt caching。

要求本身也會進入**快取金鑰**：改了要求就一定重譯，不會拿到舊要求下的譯文。

一般規則另外處理了兩件容易翻壞的事：
保留數字／程式碼／URL／換行結構，以及**把文件內容一律當成資料**——
文件裡若出現「請忽略以上指示」之類的句子，只會被翻譯，不會被執行。

### 3.2 文字：原地換字，不是重新排版

| 格式 | 作法 |
| --- | --- |
| DOCX | 走訪段落（含表格、巢狀表格、頁首頁尾），把譯文寫回**原本那個 run**，樣式、編號、圖片位置全部保留。超連結獨立成一塊翻譯，避免連結的顯示文字被併掉。 |
| PDF | 逐個文字區塊取出原文與外框 → 翻譯 → 用 redaction 塗掉原文 → 用 `insert_textbox` 把譯文寫回同一個框。塗銷時明確指定 `PDF_REDACT_IMAGE_NONE` / `PDF_REDACT_LINE_ART_NONE`，所以圖片和表格框線不受影響。 |

譯文比原文長是常態，所以 PDF 端會**自動縮小字級**直到塞得進原框；
圖片端則是二分搜尋出塞得下的最大字級。同時 prompt 也要求模型
「譯文長度盡量接近原文」，從源頭減少爆框。

PDF 端還做了兩個保護：處理前先把頁面旋轉歸零（讓讀座標與寫座標同一個座標系），
以及**跳過直排／旋轉的文字區塊**（保留原樣，寧可不翻也不要畫壞）。

### 3.3 圖片：辨識 → 翻譯 → 蓋回原位

一次 vision 呼叫同時拿到三件事（用 structured outputs 保證格式）：

```json
{"regions": [
  {"text": "Speed Limit", "translation": "速限標示",
   "bbox": [0.08, 0.12, 0.62, 0.28], "align": "center", "vertical": false}
]}
```

`bbox` 是 **0~1 正規化座標**，所以送給 API 的圖可以先縮到長邊 1568px 省錢，
重繪時仍然對得回原始解析度。

重繪是「量 → 蓋 → 寫」：

1. **量**：從框的外圈取樣推出底色，再取框內與底色差距最大的像素推出字色 —— 不靠模型猜顏色；
2. **蓋**：用底色填掉原本的文字；
3. **寫**：自動斷行（CJK 逐字、拉丁依詞）+ 二分搜尋字級，把譯文置中寫回框內。

`--image-debug-dir` 會把模型框出的位置畫成紅框存檔，方便一眼看出座標抓得準不準。

## 4. 使用方式

```bash
# 互動：先問目標語言與特殊要求
python -m tools.doc_translator 手冊.pdf

# 非互動（排程 / CI）
python -m tools.doc_translator 手冊.pdf -y -t 英文 \
    -i "保持技術手冊口吻；JetBot、ROS2 等產品名不要翻譯"

# 批次 + 術語表 + 指定輸出目錄
python -m tools.doc_translator docs/*.docx -o out/ --glossary terms.yaml

# 先試算費用
python -m tools.doc_translator 手冊.pdf --dry-run
```

互動模式長這樣：

```
========================================================
  文件翻譯（Claude API）
========================================================
待翻譯檔案：
  · 手冊.pdf

目標語言 [繁體中文]：

翻譯的特殊要求（語氣、術語、讀者對象、格式慣例…）
直接按 Enter 可略過，略過時由 Claude 自行判斷最合適的譯法。
輸入完成後，空一行結束：
  保持技術手冊的口吻
  JetBot、ROS2 等產品名保留原文
```

### 常用參數

| 參數 | 說明 |
| --- | --- |
| `-t, --to` / `-f, --from` | 目標／來源語言（來源預設自動偵測） |
| `-i, --instructions` | 特殊要求；`-` 表示從 stdin 讀。另有 `--instructions-file` |
| `--glossary` | 術語表：YAML / JSON（`{原文: 譯文}`）或 CSV |
| `--config` | 把上面這些寫成 YAML 設定檔一次帶入 |
| `--image-mode redraw\|skip`、`--no-images` | 圖片處理方式（預設 `redraw`） |
| `--image-debug-dir` | 輸出紅框標示圖，檢查座標準確度 |
| `--font` / `--pdf-font` | 指定字型檔；預設自動尋找系統 CJK 字型 |
| `--model` / `--effort` / `--image-effort` | 預設 `claude-opus-5`、文字 `low`、圖片 `medium` |
| `--concurrency` / `--max-chars-per-batch` | 並行數與每批字元上限 |
| `--dry-run` | 只統計片段數與預估輸入 token，不呼叫翻譯 |
| `--no-cache` / `--cache-path` | 譯文快取控制 |
| `-y, --yes` | 完全非互動 |

輸出檔預設與輸入同目錄，檔名加上語言標記，例如 `手冊.zh-TW.pdf`；
工具會拒絕覆蓋輸入檔。

## 5. 成本與穩定性

* **批次**：預設每批 ≤ 3000 字元 / ≤ 40 段，一次請求翻一批，而不是一句一次。
* **快取**：sqlite 譯文快取，金鑰 = 模型 + 語言 + 特殊要求 + 術語表 + 原文。重跑或多份文件共用句子時不再付費。中途 Ctrl-C 也保留已翻好的部分。
* **`--dry-run`**：用 `count_tokens`（不計費）估算輸入量與費用；沒有憑證時退回字元數粗估。
* **effort**：文字翻譯預設 `low`，圖片辨識 `medium`，需要更高品質時可調高。
* **降級而非中斷**：單一批次失敗會自動改成逐段重試；某一段真的翻不出來就保留原文；圖片辨識失敗就保留原圖。整份文件不會因為一段失敗而報廢。
* **`stop_reason` 檢查**：`refusal` 與 `max_tokens` 都會被辨識並給出可行動的訊息，不會默默吐出半截結果。

---

## 6. 已知限制（設計上的取捨）

1. **PDF 是「蓋回原位」不是重新排版**：區塊內的混合樣式（單字粗體、上標）會統一成該區塊的主要樣式；譯文縮到最小字級仍放不下時會被截斷。
2. **圖片重繪是像素層處理**：文字壓在照片或漸層上時，補丁痕跡會看得出來。底色單純的示意圖、流程圖、介面截圖效果最好。
3. **座標由模型估計**：`bbox` 偶爾會偏。先用 `--image-debug-dir` 檢查，必要時用 `--image-mode skip` 關掉圖片重繪。
4. **直排／旋轉的 PDF 文字不翻**，保留原樣。
5. **掃描版 PDF** 沒有文字層，會整頁走圖片重繪路徑 —— 能讀，但整頁重繪的品質不如有文字層的 PDF。
6. 目前只支援 PDF 與 DOCX。

## 7. 測試

```bash
python tools/doc_translator/tests/test_offline.py      # 或 python -m pytest tools/doc_translator/tests -q
```

測試用假的 `Translator` 取代 API 呼叫，驗證的是文件處理本身：
DOCX 的段落／表格／頁首與內嵌圖片有沒有正確替換、PDF 的文字有沒有被塗掉並寫回、
圖片重繪有沒有真的蓋掉原字、`--dry-run` 不會寫檔、批次切分有沒有守住上限。
**翻譯品質本身需要真的 API 金鑰才能驗證，不在離線測試範圍內。**
